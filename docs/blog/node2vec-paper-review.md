# node2vec 논문 리뷰: 그래프를 문장처럼 걷게 만들다

그래프에서 노드를 분류하거나 링크를 예측하려면 원래는 사람이 특징을 설계해야 했다. 사용자가 몇 명과 연결되어 있는지, 어떤 커뮤니티에 속하는지, 허브인지, 브리지인지 같은 신호를 도메인마다 손으로 고르는 식이다. **node2vec**는 이 과정을 한 단계 추상화했다. 그래프 위의 랜덤 워크를 문장처럼 만들고, 그 문장을 Word2Vec의 Skip-gram 방식으로 학습해 노드 임베딩을 얻는다.

이 논문의 핵심은 "랜덤 워크를 쓴다"가 아니다. DeepWalk도 이미 랜덤 워크와 Skip-gram을 결합했다. node2vec의 진짜 기여는 **어떤 이웃을 보존할 것인가를 조절 가능한 탐색 문제로 바꾼 것**이다. 같은 그래프라도 어떤 태스크는 같은 커뮤니티에 있는 노드를 가깝게 두는 게 중요하고, 어떤 태스크는 멀리 떨어져 있어도 같은 구조적 역할을 하는 노드를 가깝게 두는 게 중요하다. node2vec는 이 둘 사이를 `p`, `q` 두 하이퍼파라미터로 움직인다.

## 한 줄 요약

node2vec는 그래프를 여러 개의 노드 시퀀스로 샘플링한 뒤 Skip-gram으로 임베딩을 학습하되, 2차 편향 랜덤 워크를 사용해 **커뮤니티 유사성(homophily)** 과 **구조적 역할 유사성(structural equivalence)** 사이의 탐색 성향을 조절한다.

## 문제의식: 그래프의 "비슷함"은 하나가 아니다

노드 임베딩의 목표는 노드 `u`를 낮은 차원의 벡터 `f(u)`로 매핑해서, 이후 분류·추천·링크 예측 같은 태스크에 재사용하는 것이다. 그런데 그래프에서 두 노드가 비슷하다는 말은 두 가지로 갈린다.

- **Homophily:** 서로 연결되어 있거나 같은 커뮤니티에 속한 노드는 비슷하다. 소셜 네트워크의 친구, 논문 인용망의 같은 분야 논문이 여기에 가깝다.
- **Structural equivalence:** 직접 연결되어 있지 않아도 같은 역할을 하면 비슷하다. 서로 다른 커뮤니티의 허브, 브리지, 주변 노드가 여기에 가깝다.

DeepWalk나 LINE 같은 선행 방법은 이웃의 정의가 상대적으로 고정되어 있었다. node2vec는 이 지점을 문제 삼는다. 어떤 그래프와 어떤 태스크에서는 깊게 멀리 걸어가 커뮤니티를 잡는 편이 좋고, 다른 경우에는 출발점 근처를 촘촘히 훑어 로컬 구조를 잡는 편이 좋다. 논문은 이 선택을 고정하지 않고, 샘플링 전략 자체를 학습 파이프라인의 중요한 손잡이로 만든다.

## 방법: 2차 랜덤 워크와 `p`, `q`

node2vec의 워크는 현재 노드만 보는 1차 랜덤 워크가 아니라, **직전에 어디서 왔는지**를 함께 본다. 방금 `t → v`로 이동했고 다음 노드 `x`를 고른다고 하자. 이때 전이 확률은 엣지 가중치에 탐색 편향을 곱해 정한다.

- `p`는 **return parameter**다. 값이 작으면 방금 왔던 노드 `t`로 돌아가기 쉬워진다. 값이 크면 바로 되돌아가는 행동을 억제한다.
- `q`는 **in-out parameter**다. 값이 작으면 바깥으로 멀리 나가는 DFS 성향이 강해지고, 값이 크면 현재 노드 주변에 머무는 BFS 성향이 강해진다.

직관적으로 `q > 1`이면 가까운 이웃을 반복적으로 관찰해 구조적 역할을 더 잘 포착하고, `q < 1`이면 더 멀리 탐색해 커뮤니티 문맥을 더 잘 포착한다. 이 워크들로 노드 시퀀스를 만들면, 각 시퀀스는 자연어의 문장처럼 취급된다. 이후 Skip-gram은 중심 노드가 주변 워크 문맥의 노드를 예측하도록 학습한다.

이 설계가 깔끔한 이유는 두 가지다. 첫째, 그래프 특유의 탐색 문제를 Word2Vec 학습 문제로 연결해 계산을 단순화한다. 둘째, 임베딩 품질을 가르는 선택지를 모델 구조 내부에 숨기지 않고 `p`, `q`라는 해석 가능한 손잡이로 드러낸다.

## 실험 결과가 말하는 것

논문은 node2vec를 멀티라벨 노드 분류와 링크 예측에서 평가한다. 비교 대상은 DeepWalk, LINE, Spectral Clustering 등 당시 대표적인 네트워크 표현학습 방법이다. 저자들은 BlogCatalog, Protein-Protein Interaction, Wikipedia, Facebook, arXiv ASTRO-PH 같은 다양한 그래프를 사용했고, node2vec가 여러 설정에서 강한 성능을 보인다고 보고한다.

중요한 관찰은 단순히 "node2vec가 이겼다"가 아니다. 더 중요한 점은 **좋은 탐색 성향이 데이터셋과 태스크마다 달랐다**는 것이다. 어떤 네트워크에서는 BFS 쪽이, 어떤 네트워크에서는 DFS 쪽이 더 유리하다. 이는 논문의 출발점, 즉 그래프 임베딩에서 이웃의 정의를 고정하면 안 된다는 주장을 뒷받침한다.

링크 예측에서는 노드 임베딩 두 개를 엣지 특징으로 합성한다. Hadamard product, average, weighted-L1, weighted-L2 같은 단순 연산을 써서 `(u, v)`의 벡터를 만들고 분류기에 넣는다. 이 부분은 이후 그래프 임베딩 실험에서 자주 반복되는 표준 패턴이 되었다.

## 왜 오래 남았나

node2vec가 오래 인용되는 이유는 성능 수치보다 **프레이밍**에 있다.

1. 그래프 표현학습을 "문장 생성 + 언어모델식 학습"으로 설명해 구현과 이해의 장벽을 낮췄다.
2. DeepWalk의 아이디어를 일반화하면서도, GNN처럼 복잡한 메시지 패싱 모델로 가지 않았다.
3. `p`, `q`로 탐색 정책을 드러내 실험자가 태스크 가정과 모델 행동을 연결해 볼 수 있게 했다.
4. 노드 분류뿐 아니라 링크 예측까지 같은 임베딩으로 처리하는 재사용성을 보여줬다.

특히 집현전 관점에서는 "논문·저자·주제·인용"으로 얽힌 그래프를 다룰 때 유용한 고전이다. 그래프를 단순 검색 결과 목록으로만 보지 않고, 관계 위를 어떻게 걸을지 정하면 추천·탐색·커리큘럼 생성의 성격이 달라진다는 점을 잘 보여준다.

## 한계와 비판

node2vec는 강력하지만, 지금 기준으로 보면 한계도 분명하다.

- **속성(feature)을 직접 쓰지 않는다.** 기본 node2vec는 그래프 구조에서 나온 워크만 학습한다. 노드 텍스트, 논문 초록, 사용자 프로필 같은 풍부한 속성은 별도로 결합해야 한다.
- **동적 그래프에 약하다.** 그래프가 계속 변하면 워크를 다시 만들고 임베딩을 재학습해야 한다. 이후 dynnode2vec 같은 확장이 나온 이유다.
- **하이퍼파라미터 탐색 비용이 있다.** `p`, `q`, 워크 길이, 워크 개수, 윈도 크기, 차원 수가 모두 품질에 영향을 준다. 논문은 유연성을 얻었지만, 그만큼 튜닝 공간도 열었다.
- **귀납적 일반화가 제한적이다.** 학습 때 없던 새 노드에 대해 바로 임베딩을 만드는 능력은 GraphSAGE류의 귀납적 GNN보다 약하다.
- **의미 해석은 여전히 후처리 문제다.** 가까운 벡터가 왜 가까운지 설명하려면 워크 경로, 이웃, 커뮤니티 분석을 따로 붙여야 한다.

그래서 node2vec는 오늘날의 최종 답이라기보다, 그래프 임베딩을 이해하기 위한 기준선이자 설계 언어에 가깝다. GNN을 쓰더라도 "내 모델은 homophily를 보고 있는가, structural role을 보고 있는가"라는 질문은 여전히 유효하다.

## 집현전에 주는 힌트

집현전의 논문 탐색은 본질적으로 그래프 문제다. 논문은 논문을 인용하고, 저자는 주제를 공유하며, 사용자의 북마크는 관심사의 경로를 만든다. node2vec식 관점으로 보면 제품 설계 질문은 이렇게 바뀐다.

- 사용자가 "비슷한 논문"을 원할 때, 같은 커뮤니티의 논문을 원하는가, 같은 방법론적 역할의 논문을 원하는가?
- 인용 그래프를 탐색할 때, 가까운 후속 연구를 보여줄 것인가, 멀리 떨어졌지만 같은 구조적 위치의 논문을 보여줄 것인가?
- 커리큘럼을 만들 때, 한 주제 안에서 촘촘히 걷게 할 것인가, 여러 커뮤니티를 가로지르게 할 것인가?

node2vec의 답은 단순하다. 이 선택을 감으로 숨기지 말고, 탐색 정책으로 드러내라는 것이다. 집현전의 검색·관련논문·커리큘럼 에이전트도 결국 같은 질문을 마주한다. 좋은 그래프 제품은 "무엇을 찾을지"만 정하지 않는다. **어떻게 걸을지**를 정한다.

## 읽을 때 가져갈 것

node2vec는 그래프 표현학습의 고전이지만, 낡은 논문으로만 읽기엔 아깝다. 이 논문에서 가져갈 가장 실용적인 교훈은 다음이다.

> 그래프 임베딩의 품질은 학습 알고리즘만이 아니라, 이웃을 샘플링하는 정책에서 결정된다.

그래프를 쓰는 검색·추천·리서치 제품을 만든다면 이 문장은 아직도 유효하다. 모델이 아무리 커져도, 그래프 위에서 어떤 경로를 관찰하게 할지는 여전히 설계자의 몫이다.
